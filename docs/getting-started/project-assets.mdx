Assets are ZeroQuarry's durable record of the targets an assessment can touch. A
scan points at one or more assets, and the results of every scan flow back into
the same library, so a project accumulates a single growing picture of its
attack surface instead of a pile of one-off scan inputs.

An asset answers *what are we protecting?*; a scan answers *what did we ask about
it this time?*. That is what makes the library worth maintaining — you configure
a staging login once and every later scan authenticates the same way, and an
asset one scan discovered becomes a scan target for the next one.

![ZeroQuarry project assets with the discovery map, surface grouping, and scan policy.](/img/screenshots/project-assets.png)

## The five kinds

| Kind | Use it for |
| --- | --- |
| URL | Web apps, REST APIs, GraphQL endpoints |
| Repo | Git repositories, connected GitHub repos, uploaded source |
| Host | Hostname:port services such as SMTP, databases, internal services |
| Spec | OpenAPI/Swagger documents, GraphQL schemas, MCP server definitions |
| Docs | PDFs, Word files, or a documentation repository |

Authentication lives on the asset rather than the scan, so every scan of an asset
authenticates the same way. The kind is fixed at creation.

  blacklist.
